I. Overview
1. System Context 
The 
Veterinary Clinic Management System (VCMS)
 is a software system designed to support veterinary clinics in managing appointment scheduling, customer and pet information, medical records, and clinic operations. The system replaces manual or fragmented processes (such as paper records, phone calls, and spreadsheets) with a centralized digital platform.
The system allows 
customers (pet owners)
 to register accounts, manage their pets’ profiles, book appointments, and view the medical history of their pets. 
Clinic staff
 can manage schedules, services, and customer records, while 
veterinary doctors
 can access assigned appointments, review pet medical histories, and record diagnoses and treatments. 
Clinic owner
 oversee user management, role-based access control, and system-level reporting.
The Veterinary Clinic Management System interacts with several external entities, including human users (customers, staff, doctors, Clinic owner) and an external email service for notification delivery. The context diagram defines the system boundary and illustrates the data flows between the system and its external entities, such as appointment requests, medical records, notifications, and Clinic owner reports.
2. External Entities
The following table describes the external entities that interact with the Veterinary Clinic Management System, as identified in the system context diagram.
#
Entity
Description
1
Customer
A pet owner who uses the system to register an account, manage personal and pet information, book veterinary appointments, receive notifications, and view the medical history of their pets.
2
Laboratory staff
Personnel responsible for conducting laboratory tests (e.g., blood tests, urine tests) based on veterinary requests. They update test results in the system and ensure accurate and timely reporting for diagnosis and treatment.
3
Veterinarian 
A licensed veterinarian who accesses assigned schedules, reviews pet medical records, records diagnoses and treatments, prescribes medication or services, and provides follow-up notes.
4
Clinic owner 
System Clinic responsible for managing user accounts, assigning roles and permissions, monitoring system usage, and generating statistical reports.
5
Gmail(Email Service)
An external email service used by the system to send appointment confirmations, reminders, and other notification messages to users.
6
Receptionist
Front-desk staff who assist in managing customer check-ins, scheduling appointments, updating basic customer and pet information, and coordinating communication between customers and veterinarians.

1. Software Architecture
1.1 Overall Architectural Diagram
1.2 Component Descriptions
No
Component
Description
01
Presentation Logic Layer
Acts as the client side of the system. It sends HTTP requests to the server and receives HTTP responses. Users interact with the VMCS system through a web browser.
02
User Interface
Provides the graphical user interface of the system. JSP pages are responsible for displaying data to users and collecting user inputs before forwarding them to the Presentation Layer.
03
Presentation Logic Layer (Servlet)
Handles HTTP requests from the Web Browser. It processes user actions, controls navigation flow, validates input data, and forwards requests to the Service Interface layer.
04
Service Interface
Defines the service contracts of the system. It separates the presentation layer from business logic, ensuring loose coupling and better maintainability.
05
Service Implement
Implements business logic and use cases of the VMCS system. It processes core operations such as scheduling, customer management, veterinarian management, and clinic services.
06
Model Classes (Domain Models)
Represents business entities such as Customer, Pet, Appointment, Veterinarian, and Medical Record. These classes encapsulate system data and business rules.
07
Common Classes (Java)
Contains shared utility classes and common functions such as constants, helpers, validators, and exception handling used across multiple layers.
08
Data Access Interface (DAO Interface)
Defines methods for accessing and manipulating data in the database. It abstracts database operations to isolate business logic from data persistence details.
010
DAO JDBC Implement
Implements DAO interfaces using JDBC. It executes SQL queries, handles database connections, and maps result sets to domain models.
011
SQL Server
The relational database management system used to store and manage all persistent data of the VMCS system, including users, appointments, pets, and medical records.

6. Requirement Appendix 
6.1 Business Rules 
ID
Rule Definition
BR-01
Passwords must be stored using secure hashing (no plaintext storage).
BR-02
Role-based access control (RBAC) must be enforced: users can only access functions permitted by their assigned role.
BR-03
Inactive accounts must not be allowed to log in.
BR-04
After successful login, the system must redirect the user to the correct dashboard based on role (Clinic owner/Staff/Veterinarian/Customer).
BR-05
Registration must require accepting Terms & Privacy before creating an account.
BR-06
Appointment booking must capture owner contact information (email/phone) to support confirmations and reminders.
BR-07
The system must prevent overlapping appointments for the same time slot.
BR-08
Only authorized operational roles (Receptionist/Staff) may confirm, reschedule, or cancel appointments.
BR-09
Receptionists must be able to search appointments by date, customer, or pet; search results must not expose data outside permitted scope.
BR-10
Appointment listing and filtering must follow defined status categories (e.g., Pending, Checked-in, In Examination, Done, Canceled).
BR-11
Appointment detail actions (confirm/reject and assign/reassign doctor where permitted) must be logged and must follow role permission.
BR-12
Medical records must be protected against unauthorized access and tampering (access control + auditability).
BR-13
Reminder notifications must be sent only for confirmed appointments.
BR-14
All required fields must be validated before saving any create/update operation.
BR-15
Pet creation/editing must enforce required fields (e.g., Pet Name, Species, Date of Birth) before saving.
BR-16
Authorization must follow “deny by default”: if a permission is not explicitly granted, access must be denied.
BR-17
Users may view blog list and blog details only for published posts.
BR-18
Only clinic owners may create/update/publish/remove blog posts.
BR-19
Staff management must support search/filter and display role + status (e.g., Active, On Leave).
BR-20
Only clinic owners may manage clinic staff accounts and assign/update roles.
BR-21
Only laboratory staff can update lab test/result status (e.g., pending/completed).
BR-22
Laboratory staff must be able to upload and update examination results.
BR-23
Laboratory staff must be able to view incoming examination requests.
